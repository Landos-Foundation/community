# How Decisions Get Made (For Now)

This explains, in plain language, how Landos members currently make decisions together — before the real on-chain governance exists. If you're technical, the short version is in [README.md](README.md). This version assumes no technical background.

## The short version

Someone suggests a decision. Everyone has a week to talk about it. Then everyone votes for a week. Whatever the majority decides is what happens — Brock can still overrule it since he holds the keys during this early period, but the plan is to follow what the group decides, and if he ever doesn't, he'll say so and explain why, in writing, where everyone can see it.

This is temporary. Once Landos has a real network with real token holders and real Community Hubs, a permanent system takes over — two voting bodies (one for token holders, one for the local hub communities) that both have to agree by a two-thirds majority before anything changes, with a 90-day waiting period before it takes effect. That system doesn't exist yet, so this simpler process fills the gap.

## Who gets a vote

Anyone listed in [MEMBERS.md](MEMBERS.md). Right now, you become a member when Brock adds your name (specifically, your GitHub username — see below) to that list. Exactly what should qualify someone as a member long-term is still an open question, so this may change.

## What you need

This process runs on GitHub, the website Landos's documents already live on. If you don't have a free GitHub account yet, create one at github.com — it takes a couple of minutes. If GitHub itself is a barrier for you, reach out to Brock directly and he'll help you find another way to have your voice counted.

## Step by step

**1. Someone proposes something.**
A member writes up the decision that needs to be made and posts it as an "Issue" on the community repository (a page on GitHub where discussions happen) — a title, what's being decided, and why it matters now.

**2. One week to talk it through.**
Anyone can comment on the proposal, ask questions, or suggest changes. No voting yet — this week is just for making sure everyone understands what's being decided before anyone has to choose.

**3. The vote opens.**
After a week, a voting page is created for that proposal, with the final wording and a one-week deadline.

**4. You cast your vote.**
You vote by making a small edit to that voting page — adding your name and your choice (For, Against, or Abstain), plus a comment if you want one. On GitHub this is done by opening a "Pull Request," which is just a proposed edit to a page. If that phrase is unfamiliar, don't worry about the terminology — it just means you're submitting your vote as a tracked, timestamped edit that's tied to your account, so no one (including Brock) can quietly add, remove, or change a vote after the fact.

**5. Votes are counted.**
When the week ends, all the votes are added up. Whichever side has more wins — for now, a simple majority decides. Whether that should require more than a simple majority even at this small scale is still being worked out.

**6. The result stands — or Brock explains why not.**
Brock holds administrative control of Landos during this early period, so he technically can override any vote. The intention is not to. If he ever does, the reason gets written down in the same public record as the vote itself, not left unexplained.

## Why it works this way

There's no live Landos network yet to record votes on permanently and securely. Using GitHub in the meantime means every proposal, every comment, and every vote is public and timestamped, and history can't be quietly rewritten — the same principle the real system will run on later, just built with tools that already exist today instead of ones that don't exist yet.
